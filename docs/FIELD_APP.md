# 현장 조사 (메인 지도에서 조사원으로)

작성: 2026-11-20 밤 · 독자: 조사단, 개발자
관련: [HANDOFF.md](../HANDOFF.md) 3절 "현장 조사 → DB → 지도·길 안내", [BACKEND.md](BACKEND.md) (DB·종이 점검표 입력)

조사는 **메인 지도(`/`)** 에서 한다. 조사 결과는 바로 DB에 들어가고, 지도 색과 길 안내에 바로 반영된다.
예전 현장 조사판(`#survey`, 한 지역 `area.json`, CSV 내보내기)은 2026-11-20 밤 없앴다. 구간 번호가 DB·메인 지도와 달라 결과를 DB에 넣을 수 없었다.

## 준비

- **계정**: 관리자가 Supabase Authentication에서 계정을 만들고 `/#admin` 계정 탭에서 `surveyor`(조사원) 역할을 준다. 회원가입은 없다
- **도구**: 디지털 수평계(경사 %), 줄자(턱 높이·길 폭 cm). 폰 기울기 센서 측정은 아직 없다
- **주소**: 위치(GPS)는 HTTPS에서만 동작하므로 폰에서는 Vercel 주소로 연다

## 조사 순서

1. 메인 지도 오른쪽 패널의 **조사원 로그인** → 이메일·비밀번호
2. 지도에서 조사할 구간(선)을 누르고 **이 구간 조사하기**
3. **경사**: 구간에서 가장 가파른 곳을 디지털 수평계로 재 크기만 적는다(오르막·내리막 구분 없음. 길 안내는 양쪽 방향 모두 이 값). 횡경사는 참고
4. **장애물**: 단차(턱)는 높이 cm, 좁은 길은 폭 cm가 필수다. 계단·파손·급경사는 버튼만
   - 법 기준(편의법 시행규칙 별표1 제1호): **턱 2cm 이하·폭 1.2m 이상은 측정값으로만** 남고, **넘으면 장애물로 등록돼 길 안내에서 빠진다**. 화면에 바로 표시된다
5. **제안 등급** 확인 → 다르게 정하려면 사유 입력 → **조사 완료** (값만 남길 땐 **측정만 저장**)
   - 완료 때 DB가 다시 제안 등급을 계산한다. 앱 제안과 다르면 측정값은 저장된 채로 사유를 물어본다
6. 지도에서 그 구간이 굵은 실선(초록 통행 가능 · 노랑 주의 · 빨강 통행 어려움)으로 바뀌고, 길 안내가 그 결과를 쓴다

같은 구간을 다시 재면 측정값이 덧붙는다(덮어쓰지 않음). 길 안내는 가장 가파른 측정값을 쓴다.

## 등급 제안 기준

| 등급 | 조건 |
| --- | --- |
| 통행 가능 | 경사 ≤ 5.6%(1/18), 턱 ≤ 2cm, 폭 ≥ 1.2m |
| 주의 | 경사 5.6\~8.3%, 파손, 경사를 재지 않은 교량·터널 |
| 통행 어려움 | 경사 > 8.3%, 계단, 턱 > 2cm, 폭 < 1.2m, 보도 없는 지하차도 |

경사를 재지 않으면 DB의 추정 경사로 제안한다(4% 이상이면 '주의 이상').

## 신호가 끊겼을 때

보낼 내용은 이 기기에 대기열로 남는다. 신호가 돌아오면 패널의 **대기 중 N건 다시 보내기**를 누른다. 단계별로 보내므로 이미 보낸 측정값은 다시 들어가지 않는다.

## 조사할 수 없는 구간

OSM으로 보완한 길(단지·주차장 길·골목)과 '연결 추정' 선은 DB에 없어 조사 기록을 남길 수 없다. 화면에 그렇게 표시된다.

## 앱 없이 넣기 (예비)

앱을 못 쓰면 종이 점검표로 조사하고 `scripts/survey/survey_sheet.py`(점검표 만들기) → `scripts/survey/load_survey.py`(DB에 넣기)를 쓴다. 두 스크립트는 파이프라인 결과(`scripts/prep/out/road_city`)의 구간 번호를 쓰므로 DB와 맞다. 자세한 것은 [BACKEND.md](BACKEND.md).
